# Issue で Claude（右腕君）と話すときのガイド

GitHub の Issue に書き込むと、Claude が資料とコードを読んで、数分でコメントを返します。
チームの開発者が、要望・相談・質問に気軽に使うための仕組みです。

## 【重要】利用枠と上限

Claude は、メイン開発者が個人で契約している Claude Pro の利用枠で動いています。利用枠は Claude（アプリ）と Claude Code で共通で、5 時間ごとにリセットされる上限があり、週や月の上限がかかることもあります（[Claude ヘルプセンター](https://support.claude.com/en/articles/8324991-about-claude-s-pro-plan-usage)）。
**使い切ると、自動返信が止まるだけでなく、メイン開発者本人の Claude（アプリの開発・本番対応を含む）もリセットまで使えなくなります。**

仕組みでかけている上限：

| 項目 | 上限 |
| --- | --- |
| 自動返信の回数 | 1 日 10 回（チーム全体。日本時間 0 時にリセット）。超えると「上限に達した」とコメントされ、返信しない |
| 1 回の返信 | 最大 10 ターン・10 分 |

守ること：

1. 使うのは、出欠アプリの開発に関する要望・相談だけ。私用、ほかの仕事、雑談、関係のない調べ物には使わない
2. 質問はまとめて 1 回で書く。短い追加質問を連投しない
3. 「@claude」は入れるたびに起動する。返信が不要なコメント（お礼や人同士のやり取り）には入れない
4. 同じ依頼のやり直しは 1 回まで。それでもうまくいかなければメイン開発者に連絡
5. 重い依頼（長い資料の全文要約、大量の案出し、設計の作り直しなど）は、先にメイン開発者に相談する
6. トークン（接続の鍵）はメイン開発者個人のもの。ほかの人は扱わず、ほかのリポジトリやツールで使わない

使いすぎやルールに合わない使い方が続いた場合は、メイン開発者の判断で自動返信を一時停止します。

## 1. 使い方

1. 「Issues」→「New issue」→ テンプレート **「要望・相談」** を選ぶ
2. タイトルと「やりたいこと・困っていること」を書いて送る
3. 数分で Claude のコメントが付く（最初は「I'll analyze this…」と出て、終わると中身に書き換わる）
4. 続けて聞きたいときは、コメントに **「@claude」** を入れて書く

- 本文の先頭の「@claude」は消さない（返信の合図です）
- **1 つの Issue に 1 つの話題**。話題が変わったら新しい Issue を立てる
- 終わった Issue は「Close issue」で閉じる

## 2. 使える人

- リポジトリに **書き込み権限のある人** だけ（メイン開発者・代行の開発者。インフラ担当は GitHub の招待を承認したあとに追加）
- それ以外の人が書いた Issue やコメントには反応しません

## 3. Claude ができること・できないこと

| できる | できない |
| --- | --- |
| リポジトリの資料・コードを読む | コードの変更、ブランチやプルリクエストの作成 |
| 案・比較・確認事項をコメントで返す | 本番への反映（Apps Script・画面） |
| 「どのファイルをどう変えるか」の変更案を書く | 本番のスプレッドシート（名簿・出欠・操作ログ）を見る |

- 実際の変更は、今までどおり **人がプルリクエストを作り、自動チェックと目視チェックを通してからマージ** します（[運用ルール](OPERATIONS.md)）
- プルリクエストへのコメントでは動きません（Issue だけ）

## 4. 書かないこと（このリポジトリは公開されています）

- パスワード、トークン、API キーなどの秘密情報
- メンバーの本名・連絡先・LINE の ID
- 個人情報が写ったスクリーンショット（貼るときは名前やアイコンをぼかす）

Issue もコメントも、誰でも読める状態になります。うっかり書いたときは、すぐに編集で消して、メイン開発者に知らせてください。

## 5. 上手な頼み方

- **目的と背景** を書く（例：「ゲストに誘っていない日を見せたくない。気まずくなるため」）
- **画面のどこの話か** を書く（例：「管理者の『練習日を登録』の画面」）
- **ほしい形** を指定する（例：「案を 2〜3 個、良い点と注意点つきで」「LINE に貼れる短さで」）
- 期限があれば書く

## 6. 返信の受け取り方

- 返信は **案** です。決めるのはチーム（最終判断はメイン開発者）
- 間違えることもあります。気になる点は、コメントで「@claude ここは本当？」と聞き返してください
- 方針が決まったら、[要望と決定事項のメモ（BACKLOG.md）](BACKLOG.md) に追記します（プルリクエストで）。Claude は返信の最後に追記案を添えます

## 7. 覚えておくこと

- Claude は **Issue ごとに新しく読み直します**。別の Issue での会話や、LINE でのやり取りは覚えていません
- 毎回読む共通の知識は [CLAUDE.md](../CLAUDE.md)（Claude への指示）と [BACKLOG.md](BACKLOG.md)。大事な決定は必ずここに残す
- 返信は 1 日 10 回まで（チーム全体）。上の「【重要】利用枠と上限」を守る

## 8. うまくいかないとき

| 症状 | 確認すること |
| --- | --- |
| 返信が来ない | 本文やコメントに「@claude」が入っているか。テンプレートを使ったか |
| 「Claude encountered an error」と出る | コメントに「@claude もう一度お願いします」と書いて再実行。続くならメイン開発者へ（トークンの期限切れなど） |
| 返信が途中で切れた | 「@claude 続きをお願いします」とコメント |
| 「本日の自動返信の上限に達した」と出る | 日本時間の 0 時以降にもう一度。急ぎならメイン開発者へ |
