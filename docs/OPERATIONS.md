# 体制と運用ルール

誰が何を担当し、どの権限を持つか、変更をどう本番に出すかのルールです。
このリポジトリは公開のため、名前ではなく役割で書いています（実際の担当者は運営内で共有）。

## 1. 体制

| 役割 | 担当 |
| --- | --- |
| メイン開発者 | 開発全般（主にサーバー側）、本番への反映、GO サイン。チーム用アカウントの持ち主 |
| 代行の開発者（フロント担当） | 画面まわりの専門家。第三のレビュー担当。メイン開発者が不在のときは代わりに開発・チェック・反映を行う |
| インフラ担当 | 今後、GitHub と Google（スプレッドシート・Apps Script）の編集者として追加予定 |

## 2. 権限

| 対象 | メイン開発者 | 代行の開発者 | インフラ担当 |
| --- | --- | --- | --- |
| GitHub リポジトリ | 持ち主 | 共同編集者（書き込み） | 追加予定 |
| スプレッドシート（データ・操作ログ） | 持ち主 | 編集者 | 追加予定 |
| Apps Script（API・デプロイ・自動実行） | 持ち主 | 編集者 | 追加予定 |
| チーム用 Google アカウントのパスワード・2 段階認証 | 持ち主のみ | 共有しない | 共有しない |
| LINE Developers（ログインチャネル） | 管理者 | — | — |

- 権限は **それぞれの人の個人アカウントに共有** します。チーム用アカウントのパスワードは共有しません（2 段階認証が持ち主のスマホに届くため、また誰が操作したかを履歴で区別するため）。
- 権限の追加・削除は、持ち主がチーム用アカウントで行います。担当を外れた人の権限はその日のうちに外します。

## 3. 変更を本番に出すルール

1. **画面もサーバーも、変更はすべてプルリクエストから。**
   Apps Script も、先に `gas/Code.gs` をプルリクエストで更新し、マージしてから Apps Script に反映します。Apps Script のエディタで直接書き換えて終わりにはしません（GitHub のチェックを通らないため）。
2. **自動チェック（security-check）と目視チェック（human-check）の両方に合格してからマージ。**
   目視チェックは、できるだけ作業した本人以外が行います（メイン開発者の変更は代行の開発者が、代行の開発者の変更はメイン開発者が確認）。
3. **GitHub の「承認必須」設定は使わず、目視チェックリスト方式で運用します。**
   どちらか一人が不在でも、もう一人がチェックリストをすべて埋めればリリースできるようにするためです。一人で確認した場合は、もう一人が戻ったあとに差分を見てもらいます。
4. **Apps Script の反映**は、メイン開発者か代行の開発者が「デプロイを管理」→ 編集 → 新バージョンで行います（ウェブアプリの URL は変えない）。
5. マージ後は毎朝 9 時の見回り（妖精さん）と、8 時台の日次レポートで異常がないか確認します。

## 4. 権限を追加するとき（持ち主の作業）

| 対象 | 手順 |
| --- | --- |
| GitHub | リポジトリの Settings → Collaborators → Add people |
| スプレッドシート | チーム用アカウントで開く →「共有」→ 相手の Google アカウントを「編集者」で追加 |
| Apps Script | チーム用アカウントでプロジェクトを開く →「共有」→ 同上 |

追加したら、この資料の「2. 権限」の表を更新します（変更はプルリクエストで）。
